@AGENTS.md

## Project

Finland Landmark Tracker (V0.1): a single-page app for browsing Finland's fells, national parks and natural landmarks and marking them visited. Next.js 16 (App Router), React 19, TypeScript (strict), Tailwind CSS v4, `lucide-react` icons. Deploy target is Vercel. Landmarks load from Supabase when it is configured (V03.1), with Row Level Security on every table (V03.3), visitors can create accounts and sign in (V03.2), signed-in visitors' completed landmarks are saved to `completions` (V03.4; signed-out visitors' stay in `localStorage`), and each account has a private profile page with an avatar (V03.5).

Out of scope for now: public profiles and other social features, other countries, user-submitted landmarks, i18n.

## Commands

```bash
npm ci              # install dependencies (node_modules is needed for the Next docs referenced in AGENTS.md)
npm run dev         # dev server on http://localhost:3000
npm run typecheck   # tsc --noEmit
npm run lint        # ESLint (next core-web-vitals + typescript)
npm run build       # production build
npm run db:seed:sql # regenerate supabase/seed.sql from data/landmarks.ts
npm run test:rls    # check the RLS policies against a real project with two test users (needs .env.local)
```

There's no test framework. Before committing, run typecheck, lint and build, and check the page in a browser at mobile (390px) and desktop widths.

## Architecture

- **Data:** `data/landmarks.ts` holds the `Landmark` type and every entry: 10 fells (category `peak`; `FellsSection` sorts them tallest to lowest) 12 wilderness areas (category `wilderness-area`, with a region of "Municipality, Lapland" (cards on phones show just the municipality, like fell cards), `rank`, `wildernessScore` 1–5, size in `areaKm2`, a `reindeer` sighting likelihood from `REINDEER_LEVELS` (Very likely/Likely/Possible/Rare) with a one-line `reindeerBasis`, and a `wildlife` list that is kept but not shown; `WildernessSection` sorts them by rank) and all 41 national parks (category `national-park`, in the site owner's order, with a single `region` in Finnish (e.g. Keski-Suomi, Varsinais-Suomi) except Lapland, which stays in English (fell regions stay in English), `areaKm2` (exact in the data, rounded to whole km² in the dialog; left out for the three sea parks, which show "–"), `established` year, a `nature` list of `NatureType`s (Forest/Fell/Mire/Archipelago/Lake Scenery, plus Rivers and Rapids for Oulanka only: one type when the park is known for it, several meaning "Mixed"), and a signature `trail` with name, distance and optional duration, kept but not shown for now). `COMPLETION` names what finishing each category is called: peaks are "Conquered", parks and wilderness areas are "Visited". Use it for badges, buttons and labels rather than hard-coding the words. Fells carry extra optional fields: `difficulty` (1–5 in half steps, rendered as orange stars by `StarRating`), `hike` (name, trailhead, distance, duration, `elevationGainM`), plus `relief` and `protectedArea`, which are kept in the data but not shown for now) and `notes`, which are shown under each field in the fell dialog. Leave a field out when no reliable source exists; the dialog then shows it as "Not found" with a note for review. `lat`/`lng` are optional for the same reason. UI code never imports it directly. It goes through `lib/landmarks.ts` (`getLandmarks()`, async).
- **Map page:** `app/map/page.tsx` (server) loads every landmark and renders `Header` over a night band and a full-window `MapView` (client), which owns its own `useVisited()` and the three dialogs, and renders `LandmarkMap` (`components/LandmarkMap.tsx`). Every landmark with `lat`/`lng` gets a round button marker with its category's symbol from the home page: lucide's Mountain for fells, the two cover birds for wilderness areas and a spruce for parks (bird paths and `spruce()` live in `lib/shapes.ts`, shared with `LandmarkImage`). Markers are white with a grey symbol until completed, then take their section's colours: `bg-night`/`text-dusk` fells, pale sky `#b4c1c6`/`text-tundra` wilderness, `bg-forest` with a pale green `#adc3b0` spruce for parks. Wilderness area and park coordinates are approximate centres supplied by the site owner. Hovering or keyboard-focusing a marker previews it with `LandmarkPreview`, the bottom half of the home-page card without the picture, in that section's card colour (name, region (just "Lapland" for wilderness areas, whose municipality stays in the data), a fell's height, a small type label: Fell / Wilderness area / National park, and a dusk check when completed), in an `inert`, pointer-transparent wrapper (as wide as its content, between 16 and 22rem), placed above the marker or below it near the top edge and kept inside the map, with a triangle in the card's colour pointing at the marker; hidden when the map moves. On touch screens (`(hover: none)`) the first tap on a marker opens that preview instead of the dialog; the preview then becomes a button that opens the dialog, and a tap on the map, a map move, or a tap on another marker closes or replaces it. `MapSearch` sits top left: a search box (case- and diacritic-insensitive via `lib/search.ts`, shared with `LandmarkGrid`; Enter zooms to the matches, flying in on a single one) built as an ARIA combobox. While typing it suggests up to six landmarks in the active category whose name or any word in it starts with the text (picking one flies to it); with an empty box it lists up to five recent searches (`lib/recent-searches.ts`, localStorage key `map.recentSearches.v1`, loaded on first focus; only searches that found something are saved), each with an X (or the Delete key) to remove it. It has its own clear button in place of the browser's, and 16px text on phones (`text-base sm:text-sm`) because smaller text makes mobile browsers zoom in when the box is tapped. Next to it is one round button per category using the marker symbols (`lib/marker-icons.ts`). A pressed button (`aria-pressed`) shows only that category and inverts to a grey `#5b646b` circle with a white symbol; pressing it again shows all. While a category is picked, `CategoryProgress` shows under the controls, exactly as wide as the search box (on phones `calc(100% - 8.25rem)`, the row minus the three round buttons and their gaps, so change both together; `w-72` from `sm`; phones use a smaller title that may wrap and a smaller percentage): that category's completion ("2 of 10 conquered", a dusk percentage that counts up each time it appears, and a thin bar) on its card colour, like the home page's progress tiles. It hides while the search box is focused or holds text. Hidden markers get the `hidden` attribute on their wrapper. Where markers overlap, `stackLevel` sets each wrapper's `z-index`: completed landmarks above the rest, and within each group national parks above wilderness areas above fells; it updates with the visited state, and a hovered or focused marker rises above all (`globals.css`). Clicking a marker opens the landmark's dialog, and markers recolour as the visited state changes (it is the same store as the home page). Each button sits inside a wrapper div because MapLibre adds its own classes to the marker element. It uses `maplibre-gl` v6 with OpenFreeMap's free Positron style (no API key), fitted to Finland, with zoom and scale controls. maplibre-gl is imported inside the effect because it needs the browser, and `setWorkerUrl(new URL("maplibre-gl/dist/maplibre-gl-worker.mjs", import.meta.url))` is required: without it the bundler moves the library and its worker fails to load. The header's "Map" link sits top right.
- **Visited state (V03.4):** `hooks/use-visited.ts` returns `{ visited, ready, toggle }` from the store in `lib/visited-sync.ts` (`useSyncExternalStore`; the server snapshot is `null`, and the store's `mode` is `"loading"` until it knows who is signed in and has their list, so `ready` is false and components show skeletons, never a mismatched state). Signed out, or without Supabase settings, it uses `lib/visited-store.ts` (`localStorage` key `landmarks.visited.v1`, every access in try/catch, synced across tabs), as before accounts existed. Signed in, it holds the account's `completions` (`lib/completions.ts`): a tick shows at once and is then saved (an upsert with `ignoreDuplicates` or a delete), with saves queued so a quick double tap can't reach the database out of order; a failed save is undone and reported. Whenever the local key holds ids while someone is signed in, they are imported once (`importLocalVisits`): ids not in `landmarks` are skipped, rows are upserted with `ON CONFLICT DO NOTHING` (idempotent: safe to rerun, in two tabs, or after a failure), and only after the database confirms is the key cleared (`clearVisited()`); if it fails, the key stays and the import retries on the next page load. Who is signed in comes from the browser client's `getSession()`, re-checked whenever a page starts using the store (sign-in and sign-out happen on the server and then navigate within the app, so `onAuthStateChange` alone misses them), and the store starts each page in `"loading"` so a previous account's list is never shown. The account's list is refetched when the tab becomes visible again, to pick up other devices. `components/SyncNotice.tsx` (rendered by `Tracker` and `MapView`, read through `hooks/use-sync-notice.ts`) shows "Added N landmarks from this browser to your account" (not shown when nothing was new) and save errors at the bottom of the screen for 6 seconds.
- **Supabase:** `supabase/` is a Supabase CLI project (`config.toml`; the CLI is a dev dependency, run with `npx supabase`). `supabase/migrations/` holds the schema (`…_init.sql`) and the policies (`…_rls.sql`). Tables: `landmarks` (columns for the fields every landmark has, in snake_case, plus `sort_order` (the order of `data/landmarks.ts`) and a `details` JSONB object for everything else: hike, difficulty, nature, trail, notes, …), `profiles` (one per `auth.users` row, created by the `handle_new_user` trigger; `display_name` ≤80, `username` matching `^[a-z0-9_]{3,20}$` with a unique index, `bio` ≤160, `avatar_path` which must start with the row's own id) and `completions` (`user_id` defaults to `auth.uid()`, unique `(user_id, landmark_id)`). `lib/landmark-row.ts` converts a `Landmark` to a row and back (`landmarkToRow` / `rowToLandmark`); any field not in `COLUMN_KEYS` goes to `details`, so new optional fields need no migration. Table privileges are granted explicitly, because the project has Supabase's automatic grants turned off: anon/authenticated in the RLS migration, service_role in `…_service_role_grants.sql`. A new table needs its own grants as well as policies. RLS: everyone can read landmarks and only the service role can write them; users can read, insert, update and delete only their own profile and completions. Storage: the public-read `avatars` bucket (1 MB, JPEG/PNG/WebP) has policies on `storage.objects` letting signed-in users read, add, replace and delete files only under `avatars/<their user id>/`. `getLandmarks()` uses `lib/supabase/server.ts` (anon key, no session) when `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` are set, and throws on an error or an empty table so a broken database fails the build; without them it returns `data/landmarks.ts`, which is what dev, CI and builds without settings use. `data/landmarks.ts` stays the source: after editing it, run `npm run db:seed:sql` and run `supabase/seed.sql` (an upsert; it never deletes). Both pages set `revalidate = 3600`. `SUPABASE_SERVICE_ROLE_KEY` is only for `scripts/test-rls.ts`; never import it in app code. See `.env.example` and the README.
- **Auth (V03.2):** Supabase Auth through `@supabase/ssr`: email + password with email confirmation, Google (OAuth, PKCE) and password reset. Clients in `lib/supabase/`: `config.ts` (env and `isSupabaseConfigured`), `public.ts` (`createPublicClient`, cookie-less, only for public data such as landmarks), `server.ts` (`createClient`, async, reads the session from `cookies()`; `setAll` swallows the error Server Components raise), `client.ts` (browser) and `proxy.ts` (`updateSession`). Next 16 calls middleware `proxy.ts` (root). It runs only on `/account`, `/login`, `/signup`, `/forgot-password`, `/reset-password`, `/auth/*`, and on `/` only when the URL carries `token_hash` (an email link that fell back to the Site URL, forwarded to `/auth/confirm`). It calls `getClaims()` first, copies refreshed cookies and the no-cache headers `setAll` passes onto the response, sends signed-out visitors on `/account` and `/reset-password` to `/login?next=…`, and signed-in visitors on `/login` and `/signup` to `/account`. Home and the map never read cookies, so they stay static (check the build output: `○` with 1h revalidate); the header's `AccountLink` (client) shows "Log in" or "Account" from the browser client (`onAuthStateChange`, plus `getSession()` on every pathname change, because sign-in redirects don't remount the header) and is hidden when Supabase isn't configured. Pages live in `app/(auth)/` (shared night layout with a white `AuthCard`; form pieces in `components/auth/`); forms are client components using `useActionState` with Server Actions in `app/(auth)/actions.ts` and `app/(auth)/account/actions.ts`. Email links go to `app/auth/confirm/route.ts` (`verifyOtp` with `token_hash`, so they work in any browser; the dashboard templates must link to `{{ .RedirectTo }}?token_hash={{ .TokenHash }}&type=…&next=…`, see the README); Google returns to `app/auth/callback/route.ts` (`exchangeCodeForSession`). Auth email links and the Google return use the request's origin (`lib/site-url.ts`), so each deployment's URL must be in Supabase's Redirect URLs. Every `?next=` goes through `safeNext` (`lib/safe-next.ts`: same-site paths only). Sign-up and reset requests answer the same way whether or not the email has an account. Supabase error codes become messages in `lib/auth-errors.ts`; limits (password 8–72, display name 80) are in `lib/auth-form.ts`. `/account` is the account settings page (see Account settings).
- **Profile (V03.5):** private for now (owner only; usernames are unique so public `/u/username` pages can come later). `app/(auth)/profile/page.tsx` (dynamic) loads the profile (`lib/profile.ts`: `PROFILE_COLUMNS`, `avatarUrl`, `nameOf`, `initialOf`, `memberSince`), the visitor's `completions` with `completed_at` and `getLandmarks()`, and shows a Strava-like page in the site palette on the night layout: avatar, name, @username, bio, "Member since", "Edit profile" and "Account settings"; progress tiles in the style of the map's `CategoryProgress` card (`ProgressTile`: title and "N of M completed/conquered/visited" on the left, the percentage in dusk on the right, a thin bar below): "All landmarks" across the full width, then one tile per category in its section colour, three across at every width; phones give the category tiles a short title and "4 / 10" without the percentage, the full wording kept for screen readers; highlights (highest fell conquered, protected area explored, completions this year); and the last 8 completions with the category's marker symbol. `lib/profile-stats.ts` computes all of it. The top card is `components/profile/ProfileHeader.tsx` (client) and is edited in place: "Edit profile" turns the name, @username, bio and avatar into fields where they stand and becomes "Save changes" (with "Cancel" in place of "Account settings"); saving goes back to "Edit profile". In edit mode the fields keep the view's text sizes and positions (thin border, no vertical padding, side padding offset by a negative margin, the bio box sized to its text, the username hint shown only while invalid), so the card grows only a few pixels. The two buttons have separate React keys, because reusing one `<button>` makes the click that opens edit mode submit the form at once. Choosing a picture (JPEG/PNG/WebP, up to 10 MB) opens `AvatarCropDialog` (`react-easy-crop`, pinned at 6.2.3, in its own native `<dialog>` since `Modal`'s CSS zoom breaks the cropper's pointer maths): drag or arrow keys to move, the slider, wheel or pinch to zoom, a round crop area and a live preview circle. "Use photo" crops it to 256 px WebP (JPEG where WebP can't be encoded; `lib/avatar-image.ts`) and only previews it; nothing is uploaded until "Save changes", which uploads to `avatars/<uid>/<timestamp>.<ext>` (a new name each time, so caches never show a stale picture) and then calls the `saveProfile` Server Action (`app/(auth)/profile/actions.ts`: validates the name, username and bio again, saves them with the new `avatar_path` (or null for "Remove photo") in one update, maps 23505 to "That username is taken", deletes the previous file, and the client deletes its upload again if the save fails). It then fires a `profile-updated` window event so the header avatar reloads. The fells tile uses `bg-night-sunken` (#24292D), a shade darker than the "All landmarks" tile. `components/profile/Avatar.tsx` shows the photo (`next/image`, `unoptimized`) or the first letter of the first name on the dusk accent. The header's `AccountLink` shows that avatar (linking to `/profile`) when signed in. Signing in, confirming an email (the V03.2 template's `next=/account` is mapped to `/profile`) and `safeNext`'s fallback all land on `/profile`.
- **Account settings:** `app/(auth)/account/page.tsx` (dynamic; uses `getUser()` rather than `getClaims()` because it needs `new_email`) is one white panel (`max-w-2xl`) on the night layout. Its layout (`app/(auth)/account/layout.tsx`) loads **Inter** for this route only (`--font-inter`, used through the `font-settings` utility) so the page reads like a tool; the heading stays Manrope. Sections with small uppercase labels and rows (`components/account/Settings.tsx`: `SettingsSection`, `SettingsRow`, `settingsButton`, `dangerButton`): **Sign-in** (`EmailSetting`: change email with `updateUser({ email })`, confirmed from both inboxes, the row shows "Waiting for confirmation" while `new_email` is set; `PasswordSetting`: current password checked with a throwaway cookie-less client before `updateUser({ password })`; Google-only accounts (no `email` in `app_metadata.providers`) see neither form), **Session** (Log out = `signOut` scope local; Log out on all devices = `signOutEverywhere`, scope global), **Danger zone** (`DeleteAccount`: a native `<dialog>`, the button only enabled once `DELETE_PHRASE` is typed; the `deleteAccount` action removes the user's avatar files through the Storage API, then calls the `delete_own_account()` security-definer function (migration `…20261017000000`: deletes `auth.users` where `id = auth.uid()`, execute granted to authenticated only; profile and completions cascade), clears the cookies and redirects to `/account-deleted`). A dark "Back to profile" button closes the panel. Actions live in `app/(auth)/account/actions.ts`. Email-change links (`type=email_change`) always return to `/account?notice=email`, which says whether the other address still has to confirm. The recovery page `/reset-password` stays for the forgot-password email only.
- **Page composition:** `app/page.tsx` (server) loads landmarks and renders `Header`, `Hero`, then `app/tracker.tsx` (client) inside `main`. `Hero` is a full-width 1585×685 banner (`aspect-[1585/685]`, with a `min-h-[26rem]` floor on narrow screens) showing `public/images/hero.jpg`, cropped with `object-cover`. The photo is loaded by static import so it gets an automatic blur placeholder, and has a dark overlay plus a bottom fade into `night`. Its heading stays on one line under the custom `wide:` variant (`@media (min-aspect-ratio: 3/2)`, defined in `globals.css`) and breaks after "Your" on narrower windows. Font sizes scale with `vw`. `Header` is absolutely positioned with white text so it sits on top of the hero. `Tracker` owns the single `useVisited()` instance. It renders the progress band first, straight under the hero (`.bg-night-fade`: night, fading into mist at the bottom), holding `ProgressBar`: the overall bar with a percentage that counts up from 0 on every page load (`hooks/use-count-up.ts`, instant under reduced motion), plus one small bar per category on a tile in that section's card colour (night-raised, tundra, forest), all filled in dusk. Then the full-width `FellsSection` (fells only, `bg-mist`), then `WildernessSection` (heading, intro text, and wilderness cards in the tundra palette), then a `max-w-6xl` container on the off-white page background with the National Parks section (`LandmarkGrid`: search plus a 4-column grid of `ParkCard`s and `ParkDialog`). It shows the first 12 parks and a "Show all 41 parks" / "Show fewer" button; a search or filter always shows every match. All three sections open with the same pattern: a Manrope heading (`text-[clamp(1.5rem,2.35vw,2.75rem)]`), a one-line subheader, and a short intro paragraph. Because one `useVisited()` is shared, toggling in any dialog updates the bars immediately. The progress bars ignore search and filters.
- **Components:** `LandmarkGrid` owns the search query, the category filter and the selected landmark. Search ignores case and diacritics, so "yllas" finds "Ylläs". `FilterBar` only shows category chips when the list has more than one category. `FellDialog` (night palette), `WildernessDialog` (tundra palette) and `ParkDialog` (forest palette) all wrap `Modal`. `FellCard`/`WildernessCard` and `FellDialog`/`WildernessDialog` share the same layout, so keep them in step: the wilderness dialog has no orange box; it puts size where coordinates are and the wilderness score where difficulty is (the `reindeer` rating and `reindeerBasis` are kept in the data but not shown). Reindeer ratings rest on Metsähallitus plans and herding-cooperative figures: "Very likely" where a source names the area as a major pasture or gives a large herd there, "Likely" where only the cooperative's density (about 2 reindeer per km² everywhere) is known. Wilderness and park cards show only the name and region; their size appears only in the dialog. `ParkCard`/`ParkDialog` follow the same layout, with no orange box: size where wilderness size is, established year where the wilderness score is, and a "Nature" tile (`NatureTypes`: one type with its icon, with the islands, cotton-grass (mire) and canyon (rivers and rapids) icons drawn in `NatureIcons`, or "Mixed" with a chip per type) where the reindeer likelihood is. Dark fact tiles come from `FactTile` (`tone="night" | "tundra" | "forest"`). `FellDialog` shows elevation in an orange (`bg-dusk`) box beside the name, and fact tiles for coordinates (click to copy), difficulty stars and the typical hike (distance, duration, elevation change). The dialogs show everything without scrolling. Phones (below `sm`) use a compact layout (4:1 picture, tighter spacing and text) that fits a 390×844 screen with little room to spare, so re-check it when adding content. From `sm` up the dialogs keep their full layout (640px panel, 2:1 picture for parks and wilderness areas, 3:1 for fells with `--ridge-height: 85%` so the trim takes sky, not ridge; 18px description and fact values). `Modal` scales every dialog with CSS `zoom` as if it were `DESIGN_HEIGHT` (930px, the tallest fell dialog) tall whenever the window is shorter than that, so all three dialogs share one width and text size; it re-measures on resize and content changes, and a dialog taller than that is scaled further; the zoom is rounded down and scrolling is turned off while scaled, so no scrollbar appears. Widening the panel with a 16:9 picture would make the text smaller on laptops, since the taller picture forces more scaling. `Modal` is a native `<dialog>` opened with `showModal()`, which provides the focus trap, Esc to close and focus return. A backdrop click is detected as `event.target === dialog`.
- **Card grids:** all three sections use two columns on phones and at `sm`, and four from `lg`. On phones the cards shrink their padding and text (names `text-sm`, regions `text-xs`), fell cards show only the municipality and put the elevation in a dusk pill on the picture. All cards stay the same height across sections at every width, so check that when changing card content.
- **Images:** the wilderness placeholder is built from `Layer`s in a 400×300 space: ground layers stretch to any width and the birds keep their shape, so they aren't cropped in the 2:1 and 4:1 dialog pictures. The park placeholder is a single scene cropped to fit (`slice`), by the site owner's choice. `LandmarkImage` renders `next/image` when `landmark.image` is set. With no photo, or if the photo fails to load, it shows a gradient placeholder themed by category. Photos should be licensed (e.g. Wikimedia Commons), self-hosted under `public/landmarks/`, and credited in `imageCredit`.

## Conventions

- **Facts:** landmark facts follow Metsähallitus (luontoon.fi, formerly nationalparks.fi) first, then Wikipedia/Wikidata. Don't guess numbers. Descriptions are original text of 2–4 sentences.
- **Styling:** Tailwind v4 is configured CSS-first in `app/globals.css`, with no tailwind config file. Colors are CSS variables exposed through `@theme inline` (`bg-background`, `bg-card`, `text-muted`, `bg-subtle`, `border-border`, `bg-primary`, `bg-primary-soft`, …), plus `shadow-soft` and `shadow-lift`. Use these tokens rather than raw colors. The Finnish Fells section has its own palette taken from the hero photo: `bg-mist` (#C2C8CC) with `text-mist-ink`, dark `bg-night` cards and `bg-night-raised` tiles, `text-night-muted`, and a warm `text-dusk` accent. The Wilderness Areas section uses `--haze` (#DEE1E2, halfway between mist and the page background) via `.bg-haze-fade`, which fades from mist at its top edge to the page background at its bottom edge, so the three sections blend. Wilderness cards use `bg-tundra` (#2B3940) with `bg-tundra-raised` tiles and `text-tundra-muted`, keep the dusk accent, and show a pale-sky placeholder with soaring birds. National park cards use `bg-forest` (#23392F) with `bg-forest-raised` tiles and `text-forest-muted`, also with the dusk accent, and show spruce silhouettes under a pale sky that starts near the off-white. Fell cards without a photo show a dusk-sky placeholder with ridge silhouettes, drawn in `LandmarkImage`. The rest of the page is light only: off-white `#FAFAF7`, a single spruce-green accent `#1F6F54`, 16–24px corners. Text colors are checked against WCAG AA.
- **Fonts:** new text uses Manrope for headings (`font-heading`) and Poppins for body copy (`font-body`), both loaded in `app/layout.tsx`. Older text still uses Geist (`font-sans`) until it's restyled.
- **Interaction:** every interactive element gets a visible `focus-visible:outline-primary` ring. Motion uses `motion-safe:`, and `globals.css` disables transitions under `prefers-reduced-motion`.
- **Next 16 APIs:** use `preload` on `next/image`, not the deprecated `priority`. `LayoutProps<"/">` is a globally generated route type, not an import.
- **Imports:** `@/*` maps to the repo root.
