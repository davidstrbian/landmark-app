@AGENTS.md

## Project

Finland Landmark Tracker (V0.1): a single-page app for browsing Finland's fells, national parks and natural landmarks and marking them visited. Next.js 16 (App Router), React 19, TypeScript (strict), Tailwind CSS v4, `lucide-react` icons. Deploy target is Vercel. There's no backend: visited state lives in `localStorage`. Supabase and auth are planned for V0.2.

Out of scope for V0.1: accounts, Supabase, social features, other countries, user-submitted landmarks, i18n.

## Commands

```bash
npm ci              # install dependencies (node_modules is needed for the Next docs referenced in AGENTS.md)
npm run dev         # dev server on http://localhost:3000
npm run typecheck   # tsc --noEmit
npm run lint        # ESLint (next core-web-vitals + typescript)
npm run build       # production build
```

There's no test framework. Before committing, run typecheck, lint and build, and check the page in a browser at mobile (390px) and desktop widths.

## Architecture

- **Data:** `data/landmarks.ts` holds the `Landmark` type and every entry: 10 fells (category `peak`; `FellsSection` sorts them tallest to lowest) 12 wilderness areas (category `wilderness-area`, with a region of "Municipality, Lapland" (cards on phones show just the municipality, like fell cards), `rank`, `wildernessScore` 1–5, size in `areaKm2`, a `reindeer` sighting likelihood from `REINDEER_LEVELS` (Very likely/Likely/Possible/Rare) with a one-line `reindeerBasis`, and a `wildlife` list that is kept but not shown; `WildernessSection` sorts them by rank) and all 41 national parks (category `national-park`, in the site owner's order, with a single `region` in Finnish (e.g. Keski-Suomi, Varsinais-Suomi) except Lapland, which stays in English (fell regions stay in English), `areaKm2` (exact in the data, rounded to whole km² in the dialog; left out for the three sea parks, which show "–"), `established` year, a `nature` list of `NatureType`s (Forest/Fell/Mire/Archipelago/Lake Scenery, plus Rivers and Rapids for Oulanka only: one type when the park is known for it, several meaning "Mixed"), and a signature `trail` with name, distance and optional duration, kept but not shown for now). `COMPLETION` names what finishing each category is called: peaks are "Conquered", parks and wilderness areas are "Visited". Use it for badges, buttons and labels rather than hard-coding the words. Fells carry extra optional fields: `difficulty` (1–5 in half steps, rendered as orange stars by `StarRating`), `hike` (name, trailhead, distance, duration, `elevationGainM`), plus `relief` and `protectedArea`, which are kept in the data but not shown for now) and `notes`, which are shown under each field in the fell dialog. Leave a field out when no reliable source exists; the dialog then shows it as "Not found" with a note for review. `lat`/`lng` are optional for the same reason. UI code never imports it directly. It goes through `lib/landmarks.ts` (`getLandmarks()`, async), which is the point where Supabase gets swapped in.
- **Map page:** `app/map/page.tsx` (server) loads every landmark and renders `Header` over a night band and a full-window `MapView` (client), which owns its own `useVisited()` and the three dialogs, and renders `LandmarkMap` (`components/LandmarkMap.tsx`). Every landmark with `lat`/`lng` gets a round button marker with its category's symbol from the home page: lucide's Mountain for fells, the two cover birds for wilderness areas and a spruce for parks (bird paths and `spruce()` live in `lib/shapes.ts`, shared with `LandmarkImage`). Markers are white with a grey symbol until completed, then take their section's colours: `bg-night`/`text-dusk` fells, pale sky `#b4c1c6`/`text-tundra` wilderness, `bg-forest` with a pale green `#adc3b0` spruce for parks. Wilderness area and park coordinates are approximate centres supplied by the site owner. Hovering or keyboard-focusing a marker previews it with `LandmarkPreview`, the bottom half of the home-page card without the picture, in that section's card colour (name, region (just "Lapland" for wilderness areas, whose municipality stays in the data), a fell's height, a small type label: Fell / Wilderness area / National park, and a dusk check when completed), in an `inert`, pointer-transparent wrapper (as wide as its content, between 16 and 22rem), placed above the marker or below it near the top edge and kept inside the map, with a triangle in the card's colour pointing at the marker; hidden when the map moves. `MapSearch` sits top left: a search box (case- and diacritic-insensitive via `lib/search.ts`, shared with `LandmarkGrid`; Enter zooms to the matches, flying in on a single one) built as an ARIA combobox. While typing it suggests up to six landmarks in the active category whose name or any word in it starts with the text (picking one flies to it); with an empty box it lists up to five recent searches (`lib/recent-searches.ts`, localStorage key `map.recentSearches.v1`, loaded on first focus; only searches that found something are saved), each with an X (or the Delete key) to remove it. It has its own clear button in place of the browser's. Next to it is one round button per category using the marker symbols (`lib/marker-icons.ts`). A pressed button (`aria-pressed`) shows only that category and inverts to a grey `#5b646b` circle with a white symbol; pressing it again shows all. While a category is picked, `CategoryProgress` shows under the controls: that category's completion ("2 of 10 conquered", a dusk percentage that counts up each time it appears, and a thin bar) on its card colour, like the home page's progress tiles. It hides while the search box is focused or holds text. Hidden markers get the `hidden` attribute on their wrapper. Where markers overlap, `stackLevel` sets each wrapper's `z-index`: completed landmarks above the rest, and within each group national parks above wilderness areas above fells; it updates with the visited state, and a hovered or focused marker rises above all (`globals.css`). Clicking a marker opens the landmark's dialog, and markers recolour as the visited state changes (it is the same store as the home page). Each button sits inside a wrapper div because MapLibre adds its own classes to the marker element. It uses `maplibre-gl` v6 with OpenFreeMap's free Positron style (no API key), fitted to Finland, with zoom and scale controls. maplibre-gl is imported inside the effect because it needs the browser, and `setWorkerUrl(new URL("maplibre-gl/dist/maplibre-gl-worker.mjs", import.meta.url))` is required: without it the bundler moves the library and its worker fails to load. The header's "Map" link sits top right.
- **Visited state:** `lib/visited-store.ts` (`getVisited` / `setVisited` / `subscribe`) wraps `localStorage` key `landmarks.visited.v1`. Every storage access is in try/catch, and the store syncs across tabs. `hooks/use-visited.ts` reads it with `useSyncExternalStore`. The server snapshot is `null`, so `ready` is false during SSR and hydration and components show skeletons, not a mismatched state. Keep that shape when swapping the backend.
- **Page composition:** `app/page.tsx` (server) loads landmarks and renders `Header`, `Hero`, then `app/tracker.tsx` (client) inside `main`. `Hero` is a full-width 1585×685 banner (`aspect-[1585/685]`, with a `min-h-[26rem]` floor on narrow screens) showing `public/images/hero.jpg`, cropped with `object-cover`. The photo is loaded by static import so it gets an automatic blur placeholder, and has a dark overlay plus a bottom fade into `night`. Its heading stays on one line under the custom `wide:` variant (`@media (min-aspect-ratio: 3/2)`, defined in `globals.css`) and breaks after "Your" on narrower windows. Font sizes scale with `vw`. `Header` is absolutely positioned with white text so it sits on top of the hero. `Tracker` owns the single `useVisited()` instance. It renders the progress band first, straight under the hero (`.bg-night-fade`: night, fading into mist at the bottom), holding `ProgressBar`: the overall bar with a percentage that counts up from 0 on every page load (`hooks/use-count-up.ts`, instant under reduced motion), plus one small bar per category on a tile in that section's card colour (night-raised, tundra, forest), all filled in dusk. Then the full-width `FellsSection` (fells only, `bg-mist`), then `WildernessSection` (heading, intro text, and wilderness cards in the tundra palette), then a `max-w-6xl` container on the off-white page background with the National Parks section (`LandmarkGrid`: search plus a 4-column grid of `ParkCard`s and `ParkDialog`). It shows the first 12 parks and a "Show all 41 parks" / "Show fewer" button; a search or filter always shows every match. All three sections open with the same pattern: a Manrope heading (`text-[clamp(1.5rem,2.35vw,2.75rem)]`), a one-line subheader, and a short intro paragraph. Because one `useVisited()` is shared, toggling in any dialog updates the bars immediately. The progress bars ignore search and filters.
- **Components:** `LandmarkGrid` owns the search query, the category filter and the selected landmark. Search ignores case and diacritics, so "yllas" finds "Ylläs". `FilterBar` only shows category chips when the list has more than one category. `FellDialog` (night palette), `WildernessDialog` (tundra palette) and `ParkDialog` (forest palette) all wrap `Modal`. `FellCard`/`WildernessCard` and `FellDialog`/`WildernessDialog` share the same layout, so keep them in step: the wilderness dialog has no orange box; it puts size where coordinates are, the wilderness score where difficulty is, and the reindeer sighting likelihood (just the level as text; `reindeerBasis` is kept but not shown) where the typical hike is. Reindeer ratings rest on Metsähallitus plans and herding-cooperative figures: "Very likely" where a source names the area as a major pasture or gives a large herd there, "Likely" where only the cooperative's density (about 2 reindeer per km² everywhere) is known. Wilderness and park cards show only the name and region; their size appears only in the dialog. `ParkCard`/`ParkDialog` follow the same layout, with no orange box: size where wilderness size is, established year where the wilderness score is, and a "Nature" tile (`NatureTypes`: one type with its icon, with the islands, cotton-grass (mire) and canyon (rivers and rapids) icons drawn in `NatureIcons`, or "Mixed" with a chip per type) where the reindeer likelihood is. Dark fact tiles come from `FactTile` (`tone="night" | "tundra" | "forest"`). `FellDialog` shows elevation in an orange (`bg-dusk`) box beside the name, and fact tiles for coordinates (click to copy), difficulty stars and the typical hike (distance, duration, elevation change). The dialogs show everything without scrolling. Phones (below `sm`) use a compact layout (4:1 picture, tighter spacing and text) that fits a 390×844 screen with little room to spare, so re-check it when adding content. From `sm` up the dialogs keep their full layout (`max-w-xl`, 16:9 picture) and `Modal` scales the whole panel down with CSS `zoom` when it is taller than the window, re-measuring on resize and content changes. `Modal` is a native `<dialog>` opened with `showModal()`, which provides the focus trap, Esc to close and focus return. A backdrop click is detected as `event.target === dialog`.
- **Card grids:** all three sections use two columns on phones and at `sm`, and four from `lg`. On phones the cards shrink their padding and text (names `text-sm`, regions `text-xs`), fell cards show only the municipality and put the elevation in a dusk pill on the picture. All cards stay the same height across sections at every width, so check that when changing card content.
- **Images:** `LandmarkImage` renders `next/image` when `landmark.image` is set. With no photo, or if the photo fails to load, it shows a gradient placeholder themed by category. Photos should be licensed (e.g. Wikimedia Commons), self-hosted under `public/landmarks/`, and credited in `imageCredit`.

## Conventions

- **Facts:** landmark facts follow Metsähallitus (luontoon.fi, formerly nationalparks.fi) first, then Wikipedia/Wikidata. Don't guess numbers. Descriptions are original text of 2–4 sentences.
- **Styling:** Tailwind v4 is configured CSS-first in `app/globals.css`, with no tailwind config file. Colors are CSS variables exposed through `@theme inline` (`bg-background`, `bg-card`, `text-muted`, `bg-subtle`, `border-border`, `bg-primary`, `bg-primary-soft`, …), plus `shadow-soft` and `shadow-lift`. Use these tokens rather than raw colors. The Finnish Fells section has its own palette taken from the hero photo: `bg-mist` (#C2C8CC) with `text-mist-ink`, dark `bg-night` cards and `bg-night-raised` tiles, `text-night-muted`, and a warm `text-dusk` accent. The Wilderness Areas section uses `--haze` (#DEE1E2, halfway between mist and the page background) via `.bg-haze-fade`, which fades from mist at its top edge to the page background at its bottom edge, so the three sections blend. Wilderness cards use `bg-tundra` (#2B3940) with `bg-tundra-raised` tiles and `text-tundra-muted`, keep the dusk accent, and show a pale-sky placeholder with soaring birds. National park cards use `bg-forest` (#23392F) with `bg-forest-raised` tiles and `text-forest-muted`, also with the dusk accent, and show spruce silhouettes under a pale sky that starts near the off-white. Fell cards without a photo show a dusk-sky placeholder with ridge silhouettes, drawn in `LandmarkImage`. The rest of the page is light only: off-white `#FAFAF7`, a single spruce-green accent `#1F6F54`, 16–24px corners. Text colors are checked against WCAG AA.
- **Fonts:** new text uses Manrope for headings (`font-heading`) and Poppins for body copy (`font-body`), both loaded in `app/layout.tsx`. Older text still uses Geist (`font-sans`) until it's restyled.
- **Interaction:** every interactive element gets a visible `focus-visible:outline-primary` ring. Motion uses `motion-safe:`, and `globals.css` disables transitions under `prefers-reduced-motion`.
- **Next 16 APIs:** use `preload` on `next/image`, not the deprecated `priority`. `LayoutProps<"/">` is a globally generated route type, not an import.
- **Imports:** `@/*` maps to the repo root.
